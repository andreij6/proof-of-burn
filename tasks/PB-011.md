# PB-011 — Stable storage implementation

Wire up `MemoryManager` + stable structures for all persisted state.

## Scope
- `thread_local!` `MemoryManager<DefaultMemoryImpl>`.
- `StableBTreeMap` for proposals, commitments (composite key `(proposal_id, principal)`), votes, per-principal aggregates.
- `StableCell` for `Config` and counters; `StableLog` for an append-only audit log of burns/refunds.

## Acceptance criteria
- Insert → upgrade (`icp deploy`) → values still present (count unchanged); transient caches reset.
- Each structure on a distinct `MemoryId`.

## Notes / pitfalls
- Never store user data in `thread_local! RefCell<HashMap>` — wiped on upgrade.
- Do not serialize large heap maps in `pre_upgrade` (instruction-limit trap → bricked canister). Stable structures need no manual serialization.
