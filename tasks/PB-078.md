# PB-078 — Mobile responsiveness, loading & error states

Adapt the single-page layout to narrow viewports and define all transient states.

## Scope
- Responsive proposal cards/dashboard; define loading/error/empty states for: sign-in, follow verification, commit, threshold reached, expiry-return.

## Design source
Layout frames = `Browser` vs `Phone` (`design-system/project/pob-page.jsx`); `PageView`'s `mobile` path shows two proposals with wrapping action rows. Loading/skeleton states use `Bar` + `Gate`'s `skeleton` variant; transitions use `Reveal`; live values use `LiveDot` / `useCountUp` (`pob-kit.jsx`). Cover all five brief interactions across dark + light (`[data-theme="light"]`).

## Acceptance criteria
- Usable at mobile widths; every interaction from the brief's "Interactions to Define" has a defined loading/success/error state.

## Notes / pitfalls
- Brief lists 5 key interactions — ensure each has explicit visual treatment.
