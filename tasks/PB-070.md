# PB-070 — SPA scaffold, design system & state model

Single scrollable page (no routing) that expands in place by eligibility tier.

## Scope
- Vite SPA; `dist/.ic-assets.json5` with `enable_aliasing: true` (SPA fallback), `security_policy: standard`, `allow_raw_access: false`.
- Global app state driven by `get_eligibility` ([[PB-023]]); no routes — state changes reveal layers.
- Port the design system from the hi-fi bundle (see Design source) into the SPA's real tokens + primitives — don't re-derive the visual language.

## Design source
Authoritative hi-fi: `design-system/project/` — the foundation every other Epic-H ticket builds on.
- **Tokens** → `_ds/incentive-layer-design-system-*/colors_and_type.css` (char + `--burn` scales, Space Grotesk / Inter Tight / JetBrains Mono, 4px spacing, radii, motion, `--focus-ring`, `[data-theme="light"]`). Consume the vars — never hardcode.
- **Primitives** → `pob-kit.jsx`: `Icon, Chip, Btn, Eyebrow, Bar, HeatBar, Gate, Reveal, LiveDot, useCountUp, fmtICP, HEATS`.
- **Frame + page assembly** → `pob-page.jsx`: `Browser / Phone / PageView / TierFrame`.
- **State model** → the prototype's `PobCtx` (gating / ai / motion) is a design tweak only; real app state is the tier from `get_eligibility` ([[PB-023]]). Default heat = `HEATS.Amber`.
- Ignore the sibling `roadmap-design-system-*` bundle (another project; not wired in).

Resolves spec open question: flame metaphor is **decided** — `flame` icon + amber-orange `--burn` accent.

## Acceptance criteria
- Deployed asset canister serves the page; refreshing any in-page state returns index.html (no 404).
- `ic_env` cookie present (asset wasm ≥ 0.30.2) and read by the app.

## Notes / pitfalls
- Pin asset wasm ≥ 0.30.2 or omit version (older silently drops `ic_env`).
- One continuous view that expands — not a multi-page flow.
