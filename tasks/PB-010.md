# PB-010 — Domain data model & stable memory layout

Define the core types and assign each its own `MemoryId` partition.

## Scope
Model the entities from the specs:
- `Proposal` (id, title, topic/category, deadline, nns_proposal_id, status, threshold_e8s, total_committed_e8s).
- `Commitment` (proposal_id, principal, amount_e8s, status: Pending|ThresholdMet|Burned|Returned, created_at).
- `VoteRecord` (proposal_id, vote: Yes|No|Abstain, icp_burned_e8s, decided_at, nns_block/outcome).
- `AiReview` (proposal_id, summary, impact_score, system_prompt, tools, cached_at).
- `Config` (primary_neuron_id, admins, default_threshold, ai_price_e8s).
- Per-principal aggregates for the Tier-3 dashboard.
- Allocate `MemoryId`s (0..N) — document the map; never reuse an ID.

## Acceptance criteria
- All persisted types implement `Storable` (CBOR via ciborium, `Bound::Unbounded`).
- A written `MEMORY_ID` table in code comments matches the allocation.

## Notes / pitfalls
- Amounts in **e8s** (`u64`/`Nat`), never floats.
- Prefer `Bound::Unbounded` so adding fields later doesn't break deserialization.
