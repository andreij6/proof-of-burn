# PB-001 — Initialize icp-cli project & repo structure

Scaffold the monorepo with `icp new` and establish the backend (Rust) + frontend (asset) layout. **Use `icp`, never `dfx`.**

## Scope
- Install toolchain: `npm i -g @icp-sdk/icp-cli @icp-sdk/ic-wasm`; `rustup target add wasm32-unknown-unknown`.
- `icp new proof-of-burn --subfolder rust --define project_name=proof-of-burn --silent`.
- Repo layout: `src/backend/` (Rust crate), `src/frontend/` (SPA), `tasks/`, top-level `icp.yaml`.
- Commit `.icp/data/` (canister-id mappings); `.gitignore` `.icp/cache/` and Rust `target/`.

## Acceptance criteria
- `icp --version`, `ic-wasm --version`, `cargo` all resolve.
- `icp network start -d` then `icp deploy` builds and deploys the scaffold locally with no errors.
- Repo committed with `.icp/data/` tracked and `.icp/cache/` ignored.

## Notes / pitfalls
- Recipes must be version-pinned (unpinned references are rejected).
- No `.env` with `CANISTER_ID_*`; icp-cli injects `PUBLIC_CANISTER_ID:<name>` and the frontend reads the `ic_env` cookie.
