# PB-045 — Reentrancy & async-safety for burn/refund

Make all token-moving paths safe against interleaving and callback traps. **Gates mainnet burn.**

## Scope
- `CallerGuard` (Drop-based) per principal on `commit`, and per-proposal locks on burn/refund sweeps.
- Saga pattern for financial ops: mutate critical state (mark/deduct) before the `await`; compensate on failure; release locks in cleanup (Drop), not in regular callback code.
- Use bounded-wait calls so a stuck ledger/governance call can't block upgrades.

## Acceptance criteria
- Concurrent duplicate commits from one principal are rejected.
- A simulated callback trap leaves no double-spend / double-burn and releases locks.

## Notes / pitfalls
- Never `let _ = CallerGuard::new(..)` — that drops the guard immediately.
- A callback trap rolls back only the callback's mutations; pre-`await` mutations persist — design accordingly.
