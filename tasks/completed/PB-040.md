# PB-040 — Commit-to-burn (ICRC-2 approve + escrow)

Let a Tier-2 user commit an amount of ICP toward a proposal, escrowed by the backend until threshold resolution.

## Scope
- Frontend: user calls ICP ledger `icrc2_approve` granting the backend an allowance (amount + fee).
- Backend `commit(proposal_id, amount_e8s)`: validate cap ([[PB-044]]), then `icrc2_transfer_from` user → a per-proposal canister subaccount; record `Commitment{Pending}` and bump `total_committed_e8s`.
- Idempotent: set `created_at_time`; reject double-submit via the caller guard ([[PB-045]]).

## Acceptance criteria
- Commit moves ICP into escrow and updates threshold progress ([[PB-041]]).
- Insufficient allowance / funds returns a typed error, no state change.

## Notes / pitfalls
- ICRC-2 is two-step: approve THEN transfer_from (else `InsufficientAllowance`).
- Handle every `TransferFromError` variant; on `BadFee` use the ledger-reported `expected_fee`.
- Transfers initiated from backend, never frontend.
