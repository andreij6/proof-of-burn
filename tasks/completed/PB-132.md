# PB-132 — PoolNeuron data model + POOL_NEURONS storage + cached pool stats

Add the pool registry data structures and stable storage. Plan §1.

## Backend
- Add `PoolStatus = enum { Draft, Active, Inactive }` (Candid variant).
- Add `PoolNeuron` struct: `neuron_id`, `registered_by: Principal`,
  `voting_power`, `status: PoolStatus`, `created_at`, `activated_at: Option<u64>`,
  and saga block fields `treasury_block`, `backend_cmc_block`,
  `frontend_cmc_block` (all `Option<u64>`). `impl_storable!(PoolNeuron)` (CBOR
  field-map, serde defaults).
- Add `POOL_NEURONS: StableBTreeMap<u64 /*neuron_id*/, PoolNeuron>` at
  `MemoryId::new(8)` (confirmed free).
- Add `CACHED_POOL_INFO` thread-local cell:
  `{ total_pool_voting_power, active_count, updated_at }`.
- Add a pure helper `recompute_pool_info()` that sums voting power over `Active`
  neurons and writes `CACHED_POOL_INFO`.

## Acceptance Criteria
- [ ] `POOL_NEURONS` initialises at `MemoryId::new(8)` without colliding with
      existing memory ids (0–7).
- [ ] `PoolNeuron` round-trips through stable storage (insert/get unit test).
- [ ] `recompute_pool_info()` counts only `Active` neurons (Draft/Inactive
      excluded) — unit test with a mix of statuses.
- [ ] Upgrade safety: adding these structures does not break an upgrade from a
      canister without them.
