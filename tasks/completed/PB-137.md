# PB-137 — Pool read queries: `get_pool_info` + `get_my_pool_neuron`

Query endpoints the frontend needs for the sidebar, the leader-card pooled-VP
line, and draft resume. Plan §6, §7.

## Backend
- `get_pool_info() -> PoolInfo` (query): returns total pooled voting power
  (Active only), active count, and the list of **Active** pool neurons (neuron_id,
  voting_power, registered_by, rank by VP desc). Reads `CACHED_POOL_INFO` for the
  totals; lists from `POOL_NEURONS`.
- `get_my_pool_neuron() -> opt PoolNeuron` (query): the caller's own entry in any
  status (Draft/Active/Inactive) so the UI can resume a Draft. Returns `None` for
  anonymous or no entry.

## Acceptance Criteria
- [ ] `get_pool_info` totals match the sum of Active neurons' voting power and
      exclude Draft/Inactive.
- [ ] The returned list is sorted by voting power descending (so the UI can mark
      top-25 payout-eligible).
- [ ] `get_my_pool_neuron` returns the caller's Draft/Active/Inactive entry, or
      `None` when there is none / caller is anonymous.
- [ ] Both are `query` calls (no state mutation) and bounded in cost.
