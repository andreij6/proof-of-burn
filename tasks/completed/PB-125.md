# PB-125 — Split settled proceeds 50% treasury / 25% backend cycles / 25% frontend cycles

When a proposal settles with a vote (is_voted), each committed amount is split
instead of fully burned:
- **50%** → treasury subaccount (held as ICP, admin-withdrawable, PB-126)
- **25%** → backend canister cycles (CMC notify_top_up → backend)
- **25%** → frontend canister cycles (CMC notify_top_up → frontend)

## Backend
- Increase the per-commit escrow reserve so three outgoing transfers' fees are
  covered (target + 540_000 instead of +520_000); update frontend deposit/fee UI.
- Add `frontend_canister_id` to Config (serde default) + lazy fallback by
  is_local (local a2cb4-…, mainnet kyclk-…) + `admin_set_frontend_canister`.
- Settlement: replace single burn with the 3-way split; track per-step block
  indices for idempotent retry (extends PB-111). Refund path unchanged.

## Tests
- Unit: split math (50/25/25, rounding remainder).
- Integration: settled commitment moves 50% to treasury and 25%+25% toward CMC;
  retry doesn't double-move.
