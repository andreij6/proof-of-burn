# PB-113 — Arithmetic & input hardening

Cluster of defensive-coding gaps found in review. Individually low-to-medium, collectively worth closing before mainnet.

## Findings

### F-104 — No `overflow-checks` in release build
The workspace has no `[profile.release] overflow-checks = true`. In wasm/release, integer overflow **wraps silently**. Combined with the unchecked `+=` below this means a wrap is possible (if improbable).

### F-105 — Unchecked arithmetic in commit / settlement
`src/backend/src/lib.rs`: `proposal.adopt_pot_e8s += target_e8s`, `reject_pot_e8s +=`, `total_committed_e8s +=` (commit), and `agg.total_burned +=` (settlement) are plain `+=`. Use `saturating_add`/`checked_add`.

### F-106 — `admin_set_proposal_deadline` underflow footgun
Only checks `deadline != 0`. A deadline smaller than the 1-hour cutoff (`3_600_000_000_000` ns) makes `deadline - 3_600_000_000_000` underflow → wraps to a huge value → `commit` and `proposal_sync_sweep` never see the cutoff → commits permanently allowed and the proposal never settles (funds locked). Validate `deadline > now + cutoff`.

### F-107 — `get_treasury_balance` is an unauthenticated update
It's an `update` that makes an inter-canister call and is callable by any authenticated principal (anonymous is blocked by `inspect_message`). Minor cycle-drain / info-disclosure vector. Consider `require_admin` or convert to a cached query.

## Scope
- Add `[profile.release] overflow-checks = true` to the workspace `Cargo.toml`.
- Replace the unchecked `+=` sites with checked/saturating arithmetic returning a typed error where appropriate.
- Validate deadlines in `admin_set_proposal_deadline` (must be at least `now + cutoff + margin`).
- Gate `get_treasury_balance` behind `require_admin` (or document why it's public).

## Acceptance criteria
- Release build traps (not wraps) on overflow; targeted unit tests assert checked-add behaviour at boundaries.
- Setting a too-soon deadline is rejected with a typed error.
- Treasury balance is not readable by arbitrary callers (or the decision is documented).

## Notes / pitfalls
- Enabling `overflow-checks` slightly increases wasm size — acceptable for a value-holding canister.
