# PB-122 — Option C: self-attested follow; cap commits by wallet, not neuron stake

## Problem
The app can't prove neuron ownership. Internet Identity issues a **different
principal per dapp**, so the app-login principal can never equal the user's NNS
principal (which controls their neuron). The old `check_nns_follow` did
`neuron.controller == caller` (app principal) — impossible to satisfy on mainnet —
and `get_full_neuron` would be rejected anyway since the canister isn't a hotkey
on arbitrary neurons. Tier-2 was effectively unreachable on mainnet.

Options considered: A) two-hotkey proof (canister + app principal as hotkeys),
B) single hotkey weak binding, C) drop neuron verification and lean on the burn,
E) certified frontend proof. **Chose C** — the real skin-in-the-game is the ICP
burn, not the neuron stake.

## Change
- Backend: removed `check_nns_follow`, `register_neuron`, `verify_follow` and the
  `Neuron`/`Followees`/`Result_2` types. Added `confirm_follow()` — a self-attested
  flag (no NNS call). Removed the per-commit `EXCEEDS_STAKE_CAP` check; commits are
  capped by wallet balance via the escrow deposit requirement. `get_eligibility`
  `holdings_e8s` is now 0 (no stake cap). `.did` updated.
- Frontend: "Follow neuron" button opens an instructions dialog (how to follow on
  the NNS) with **No thanks** / **Done**. Done → `confirm_follow()` → Tier 2, can
  vote. Removed the neuron-id input, hotkey instructions, and "Stake cap" displays.
- Tests updated (saga uses `confirm_follow`); 31 unit + 11 integration + 52 frontend green.

## Note
Following is encouraged (UI) but not enforced. If governance-weighted caps are
wanted later, Option A (hotkey proof) can be added as a verified upgrade.
