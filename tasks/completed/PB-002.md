# PB-002 — Author `icp.yaml` (canisters, recipes, local II)

Define the project's canisters and environments.

## Scope
- `backend` canister via `@dfinity/rust@v3.2.0` recipe (`configuration.package: backend`, `candid: backend/backend.did`).
- `frontend` canister via `@dfinity/asset-canister@v2.1.0` (`dir: dist`, `build: [npm install, npm run build]`).
- `networks: - name: local, mode: managed, ii: true` to deploy Internet Identity locally.
- `environments` array for `staging` and `production` (both `network: ic`, with a raised `freezing_threshold` on backend for prod).

## Acceptance criteria
- `icp project show` renders the expanded config with both canisters.
- `icp deploy` builds backend + frontend in parallel locally; II reachable at `http://id.ai.localhost:8000`.

## Notes / pitfalls
- Arrays, not maps, for `networks`/`environments`.
- With a recipe, only `name`, `recipe`, `sync`, `settings`, `init_args` are valid canister fields; recipe-specific keys go under `recipe.configuration`.
- Deploy to mainnet with `-e ic`, not `--network ic`.
