# PB-117 — Live NNS proposal feed (replace mock seeding)

**Hard mainnet blocker.** The app has **no live proposal data**. `init` /
`post_upgrade` call `seed_mock_proposals()` which inserts three hard-coded,
long-closed proposals (138402, 138388, 138376). There is no path that fetches
real open NNS proposals.

## Why this blocks launch
- Users would see and commit ICP to **fake/stale proposals**.
- When a threshold is met, the canister calls `RegisterVote` on those NNS ids,
  which are closed → NNS rejects → (post [[PB-110]]) proposal marked `"failed"`
  → ICP refunded. So no real governance ever happens; users just churn fees.
- The whole value proposition (steer live NNS votes) is absent.

## Scope
- Periodically fetch open NNS proposals via an inter-canister call to NNS
  Governance (`rrkah-fqaaa-aaaaa-aaaaq-cai` → `list_proposals`), filtered to
  votable topics and not-yet-decided status.
- Map each to an internal `Proposal` with `nns_proposal_id` set to the real id
  (consumed by [[PB-115]]), a derived internal key, threshold, and a deadline
  aligned to the NNS proposal's voting deadline.
- Add new proposals on a timer; mark/close internal proposals when the NNS
  proposal leaves the votable window. Respect `MAX_PROPOSALS`.
- Gate `seed_mock_proposals()` to local only (like the other dev fallbacks),
  so production never shows mock data.
- Decide threshold per proposal (flat default for v1) and deadline cutoff.

## Acceptance criteria
- On mainnet, the proposal list reflects currently-open NNS proposals; no mock
  proposals are present.
- A committed, threshold-met proposal casts a real vote against the live NNS
  proposal id and burns on success.
- Local dev still works (mock seed retained behind `is_local`).
- Covered by integration tests with a stub NNS `list_proposals` (extends
  [[PB-112]]).

## Notes / pitfalls
- `list_proposals` payloads can be large — page and cap; only store the fields
  the UI/voting need.
- Voting deadline vs. the app's 1-hour commit cutoff must be derived from the
  real NNS proposal deadline, not a fixed offset from "now".
- The canister must be able to read neuron/proposal data — confirm no hotkey is
  needed for `list_proposals` (public) even though `get_full_neuron` needs one.
