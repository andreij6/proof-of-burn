# PB-110 — Remove unsafe NNS "mock fallback" that bypasses verification on mainnet

**CRITICAL — gates mainnet. Two functions silently treat NNS call *rejections* as success.** These fallbacks were added so local dev works without a real NNS Governance canister, but on mainnet they are exploitable / fund-destroying.

## Findings

### F-101 — `check_nns_follow` grants eligibility + fake stake on rejection
`src/backend/src/lib.rs` (~line 557): when the `get_full_neuron` call is rejected with `DestinationInvalid`, `CanisterError`, or `CanisterReject`, the function returns `Ok((true, 100_000_000_000))` — i.e. **"following = true, stake = 1000 ICP."**

Impact on mainnet:
- Any authenticated user can pass `register_neuron` / `verify_follow` whenever the NNS call rejects (e.g. a neuron_id that triggers a reject, or any transient NNS error).
- The controller check (`neuron.controller != Some(caller)`) is skipped entirely in the reject path.
- `cached_stake_e8s` is set to a fake 1000 ICP, inflating the per-user commit cap (`EXCEEDS_STAKE_CAP`).
- Net effect: the entire Tier-2 follow gate — the core mechanism — is bypassable.

### F-102 — `cast_nns_vote` reports a rejected vote as successful
`src/backend/src/lib.rs` (~line 1151): on `DestinationInvalid` / `CanisterError` / `CanisterReject` the function returns `Ok(())`. In `process_proposal_cutoff` that marks the proposal `"voted"`, which then **burns all committed ICP** in `settle_proposal_commitments` even though no vote was actually cast.

## Scope
- Gate the mock fallback to local only. Detect local via the configured ledger canister id (mainnet ICP ledger = `ryjl3-tyaaa-aaaaa-aaaba-cai`) or an explicit `is_local` flag stored in `Config` at init.
- On mainnet: a rejected `get_full_neuron` must return `Err` (no eligibility granted); a rejected `manage_neuron` vote must return `Err` so the proposal goes to `"failed"` and commitments are **refunded, not burned**.
- Add a `Config.is_local: bool` (set in `init` from the existing owner check) rather than re-deriving environment in each function.

## Acceptance criteria
- On a simulated mainnet ledger id, a rejected NNS call yields `Err` and does **not** grant follow/stake or burn ICP.
- On local, behaviour is unchanged (dev flow still works).
- Covered by integration tests (see [[PB-112]]).

## Notes / pitfalls
- This is the highest-severity finding in the codebase. Do not deploy to mainnet until both F-101 and F-102 are fixed and tested.
- `cached_stake_e8s` is captured at registration and never re-validated (TOCTOU) — acceptable for v1 but note it here.
