# PB-134 — `create_pool_draft` (verify before pay; no payment)

Phase 1 of joining the pool: verify ownership (canister hotkey) and follow, then
persist the neuron as a **Draft** with no funds moved. Plan §2 Phase 1,
decisions #1 and #2.

## Backend
- `create_pool_draft(neuron_id: u64) -> Result` (update):
  1. `require_authenticated` + `CallerGuard`.
  2. **First-come binding:** if `neuron_id` exists with a different
     `registered_by`, reject `ALREADY_REGISTERED`.
  3. **Verification** (skipped when `config.is_local`):
     - `get_full_neuron(neuron_id)`.
     - Assert `ic_cdk::id()` ∈ `hot_keys`, else `HOTKEY_MISSING`.
     - Assert the neuron follows the primary leader on `TOPIC_GOVERNANCE`, else
       `NOT_FOLLOWING`.
     - Read voting power.
  4. Upsert `PoolNeuron { status: Draft, registered_by: caller, voting_power,
     created_at: now }`. Audit-log `pool_draft`. **No funds touched.**
- Distinct, machine-readable error strings (`HOTKEY_MISSING`, `NOT_FOLLOWING`,
  `ALREADY_REGISTERED`) so the wizard can show which check failed.

## Acceptance Criteria
- [ ] On valid hotkey + follow, a `Draft` `PoolNeuron` is created bound to the
      caller; no ledger transfer occurs.
- [ ] Missing canister hotkey → `HOTKEY_MISSING`; not following leader →
      `NOT_FOLLOWING`; neuron owned by another principal → `ALREADY_REGISTERED`.
- [ ] On `is_local`, verification is skipped and a Draft is created (enables local
      manual testing).
- [ ] A Draft is **not** counted by `recompute_pool_info()`.
- [ ] Re-calling for the same caller/neuron updates the existing Draft (idempotent
      upsert, refreshed voting power).
- [ ] Unit/integration tests cover each branch with a mocked `get_full_neuron`.
