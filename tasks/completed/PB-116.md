# PB-116 — Frontend must use the configured primary neuron, not a hard-coded ID

The SPA hard-codes neuron `4821667` in `src/frontend/src/App.tsx`:
- `register_neuron(4821667n)` — the Follow button registers this neuron
- `clipboard.writeText("4821667")` — the copy-neuron button
- display strings `Neuron 4.821.667` and `VP 4,821,667`

On mainnet the backend votes with the configured `primary_neuron_id`
(`17802688826615984104`). If the frontend keeps the literal, users are told to
follow — and `register_neuron` submits — the **wrong** neuron, so follow
verification and the whole Tier-2 gate break.

## Scope
- Read `primary_neuron_id` from `get_config()` on load and use it everywhere the
  neuron is registered, copied, or displayed.
- Format the display with grouping (the value is a u64 that exceeds JS safe-int —
  keep it a `bigint`/string; never `Number()` it).
- Remove all three `4821667` literals.

## Acceptance criteria
- Follow/register, copy, and display all reflect `get_config().primary_neuron_id`.
- Works for `17802688826615984104` without precision loss (no Number coercion).
- Verified against a backend configured with the production neuron id.

## Notes / pitfalls
- `17802688826615984104 > Number.MAX_SAFE_INTEGER` — must stay BigInt end to end.
- Pairs with [[PB-115]] (backend voting against the right NNS proposal id) and the
  MAINNET.md B2 pre-flight blocker.
