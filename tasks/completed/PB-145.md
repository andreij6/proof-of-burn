# PB-145 — Backend tests (unit + PocketIC) for pooling

Comprehensive automated coverage for the pool feature. Plan §8 (Automated).

## Tests
- **create_pool_draft:** valid hotkey+follow → Draft; `HOTKEY_MISSING`;
  `NOT_FOLLOWING`; `ALREADY_REGISTERED`; Draft excluded from VP/payouts. Mock
  `get_full_neuron` responses.
- **finalize_pool_registration:** `NO_DRAFT`; `INSUFFICIENT_DEPOSIT`; success →
  50/25/25 split + Active; saga idempotency (retry doesn't double-spend).
- **cancel_pool_draft / unregister_leader_neuron:** owner/non-owner + status
  guards; cancel frees the neuron; unregister → Inactive, no refund.
- **refund_registration:** returns escrow; idempotent (empty → no-op).
- **distribute_pool_rewards:** top-25 selection over Active; equal-split math;
  empty pool → treasury keeps it; `pool_distributed` prevents re-pay.
- **refresh/inactivation:** follow-broken / 0-stake → Inactive; resilient to a
  single `get_full_neuron` failure.
- Run: `cargo test -p backend`.

## Acceptance Criteria
- [ ] All listed unit tests pass.
- [ ] At least one PocketIC integration test covers an end-to-end
      draft → fund → finalize → settle proposal → pool payout flow.
- [ ] Saga idempotency test proves no double-spend on finalize retry.
- [ ] `cargo test -p backend` is green with no ignored pool tests.
