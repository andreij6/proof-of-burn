# PB-184 — Tests: host + PocketIC end-to-end + vitest suites

The release gate for the reviewer. Plan §5.

## Host unit (already partially specified in PB-180..182 — consolidate)
- Price guard rails; cache-hit-no-charge; deletion boundary
  (1↑/2↓ vs 2↑/2↓); double-vote; stale-generation vote; saga retry after
  mocked LLM failure (no re-charge); prompt truncation invariant.

## PocketIC (src/backend/tests/integration.rs)
- Full lifecycle: fund escrow → `request_ai_review` (mock generation on
  local config) → treasury +50% of 3 ICP on-ledger → second identity reads
  the review free → two downvotes delete it → `get_ai_review` null →
  re-request creates generation 2 and charges again.
- Rejections: flag off (`FEATURE_DISABLED`); unknown proposal;
  underfunded escrow; anonymous caller.
- Race: identity B calls `request_ai_review` after A's review exists ⇒
  B uncharged, `refund_ai_deposit` returns B's escrow.

## Vitest
- PayDialog/ReviewDialog state machines; vote UI incl. deletion path;
  price formatting from config; lazy-fetch caching by proposal id.
