# PB-181 — Backend: request_ai_review — payment saga, ic-llm call, local mock, retry sweep

The core flow: pay 3 ICP → generate via the DFINITY LLM canister → cache.
Plan §2–3, decisions #1/#3/#7/#8.

## Backend
- `cargo add ic-llm@1.1` (pin minor). Model constant
  `AI_REVIEW_MODEL = Model::Llama4Scout`; store `"llama4-scout"` string on
  the review. `PROMPT_VERSION: u16 = 1`.
- Prompt builder (pure fn, unit-testable): system message (analyst persona
  + required sections: TL;DR / who benefits–who pays / network &
  tokenomics impact / risks / verdict with confidence, plain text) + user
  message (id, title, category, summary truncated to 8 KiB with a
  `[summary truncated]` marker). Assert total < 10 KiB (LLM canister cap).
- `request_ai_review(nns_proposal_id) -> Result<AiReviewView>`:
  1. auth + `ai_reviewer` flag + `CallerGuard` + per-proposal lock
     (ProposalLock-style set keyed by nns id — no double generation).
  2. cache hit (`Ready`) ⇒ return cached, charge nothing (escrow untouched;
     caller reclaims via `refund_ai_deposit`).
  3. proposal must exist in `PROPOSALS`; escrow ≥ `ai_price_e8s + 3×10_000`.
  4. journal `AiReview{PendingPayment, generation: prev+1}` → 50/25/25
     split with per-step block guards + CMC notify (reuse
     `call_cmc_topup_transfer` / `notify_cmc_topup`) → `Generating`.
  5. generation: wasm32 + !is_local ⇒ `ic_llm::chat(...).send()`;
     is_local / host-test ⇒ deterministic canned review embedding the
     proposal id (house mock pattern). Success ⇒ `content`, `generated_at`,
     `Ready`. Failure ⇒ `FailedGeneration` (payment stays settled).
  6. audit `ai_review_paid` (amount = fee) and `ai_review_ready`.
- Sweep `retry_failed_ai_reviews()` (timer + `admin_trigger_sweep`):
  re-runs generation only for `FailedGeneration`; never re-charges.

## Acceptance Criteria
- [ ] Cache hit charges nothing (escrow balance unchanged — host test).
- [ ] Underfunded escrow ⇒ `INSUFFICIENT_DEPOSIT`; nothing journaled.
- [ ] Mid-split ledger failure → sweep completes payment AND generation
      with zero double-spend (block-guard test).
- [ ] LLM failure after payment → `FailedGeneration` → sweep retry ends
      `Ready` without new transfers.
- [ ] Prompt builder truncation + <10 KiB invariant unit-tested.
- [ ] Unknown proposal id ⇒ `PROPOSAL_NOT_FOUND` before any transfer.
