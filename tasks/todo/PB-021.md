# PB-021 — Backend caller authentication

Bind actions to `msg_caller()` and reject anonymous on all participation endpoints.

## Scope
- All commit/review/participation update methods guarded with `require_authenticated`.
- Use the caller principal as the identity key for commitments and aggregates.

## Acceptance criteria
- Anonymous calls to participation methods are rejected.
- Per-principal state correctly keys off `msg_caller()`.

## Notes / pitfalls
- If anonymous is allowed and used as an identity key, it becomes a shared identity anyone can use.
- Capture `caller` at function entry (safe across `await`).
