# PB-074 — Burn commitment UI (Tier 2)

Per-card input + Commit button, with cap and confirmation.

## Scope
- Amount input with inline cap (≤ holdings — [[PB-044]]); approve+commit flow ([[PB-040]]); confirmation + success state.
- Live threshold progress bar; "no burn, funds returned" reassurance for unmet proposals.

## Design source
Recreate the `canCommit` (Tier 2+) block of `ProposalRow` (`design-system/project/pob-parts.jsx`): amount input + primary `flame` "Commit" `Btn`; the `coins` "Holdings … · cap enforced" line; live `HeatBar`. Confirmation/success reuse the `mineBadge` states (`dashed` "You · pending" → `burn` "You · burning soon").

Resolves spec open question: the no-burn guarantee is **reassurance, not warning** — render it as the `undo`-icon line "No burn if threshold misses — committed ICP is returned." in muted `--fg-3`, never error styling.

## Acceptance criteria
- Validates against holdings; runs approve→commit; shows pending→met→burned/returned states.
- Over-cap input is blocked client-side and rejected server-side.

## Notes / pitfalls
- Communicate the "no burn if threshold not met" guarantee as reassurance, not a warning (spec open question).
