# PB-182 — Backend: review voting, net-negative deletion, generation bump

Community quality control: votes are free, bad reviews self-destruct.
Plan §2, decisions #4/#5.

## Backend
- `vote_ai_review(nns_proposal_id, generation: u32, up: bool)
  -> Result<opt AiReviewView>`:
  - auth + `ai_reviewer` flag; review exists, `Ready`, and `generation`
    matches the current one (stale generation ⇒ `STALE_GENERATION`).
  - one vote per principal per generation
    (`AI_REVIEW_VOTES` key `(id, generation, caller)`; duplicate ⇒
    `ALREADY_VOTED`). The sponsor may vote like anyone else.
  - apply count; **if `downvotes > upvotes`**: delete the review row,
    delete that generation's vote rows, audit `ai_review_deleted`
    (user = the tipping voter), return `null`.
  - otherwise return the updated view (with `my_vote`).
- Deletion does NOT refund the sponsor (the service was rendered);
  document in the candid comment.
- Vote rows for old generations are pruned on deletion AND lazily when a
  new generation is created (bounded storage).
- ⚠ Owner veto point honored from the plan: deletion threshold is
  net-negative; a literal "any downvote deletes" variant must be a
  trivially visible 2-line change (single comparison + comment).

## Acceptance Criteria
- [ ] 1↑/2↓ deletes; 2↑/2↓ survives (boundary host tests).
- [ ] Double vote rejected; vote on stale generation rejected.
- [ ] After deletion, `get_ai_review` returns null and a re-request
      creates `generation + 1` with zeroed votes.
- [ ] Old-generation vote rows cannot influence the new review (test).
- [ ] Audit log contains paid / ready / deleted events in order.
