# PB-170 — Tests: PocketIC end-to-end + vitest determinism suite

The release gate for enabling the `mini_golf` flag anywhere. Plan §7.

## PocketIC (src/backend/tests/integration.rs)
- Full happy path: fund escrow → `start_golf_round` → fee split lands
  (treasury +50%) → `submit_golf_score` with a valid par-line shot log →
  weekly AND monthly leaderboard rows exist with correct strokes.
- Rejections: flag off; double-start inside TTL; submit after expiry;
  structural-validation failures (bad stroke counts, power > 1000);
  foreign-round submission.
- Period boundary: two submissions with canister time advanced across a
  week boundary land in different weekly periods, same monthly period.

## Vitest
- Physics determinism: golden vectors + 100× replay identity (PB-164 suite
  promoted to CI-required).
- Quantization: drag vector → shot encoding edge cases (zero drag, max
  power clamp).
- Leaderboard/page logic: countdown math, rank/par-relative formatting.

## Acceptance Criteria
- [ ] `cargo test -p backend` and `npm test` green with all new suites.
- [ ] Local verification runbook executed once end-to-end (documented in
      the task close-out): faucet → pay → play dev course → submit →
      row visible at `frontend.local.localhost:8000`.
- [ ] Treasury delta verified on-ledger, not just via canister state.
