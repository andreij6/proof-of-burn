# PB-073 — Progressive-disclosure tier engine

Reveal/lock UI layers in place based on the eligibility tier.

## Scope
- Map tiers 0–3 to visible/locked component sets using visual state changes (blur/lock overlays, expanding sections, greyed controls) — no redirects.
- Transitions on sign-in, follow-verified, first-commit.

## Design source
Use the prototype's gating + reveal mechanics from `pob-kit.jsx`: `Gate` (visible-but-locked overlay with an unlock-hint `Chip`; `blur` / `skeleton` / `faded` variants, default `blur`) and `Reveal` (staggered fade/blur-up). Tier ladder + copy = `TIER_META` (`pob-parts.jsx`); tier-driven composition = `PageView` (`pob-page.jsx`).

Resolves spec open question: locked Tier 2/3 features are **visible but gated** (via `Gate`), not hidden. The prototype's `PobCtx` toggle is a design tweak only — gate real actions on `get_eligibility` ([[PB-023]]).

## Acceptance criteria
- Moving across tiers reveals exactly the layers specified in the brief, with smooth in-place transitions.
- Reload preserves the correct tier from `get_eligibility`.

## Notes / pitfalls
- Drive entirely from backend eligibility ([[PB-023]]); never trust client-only flags for gating real actions.
