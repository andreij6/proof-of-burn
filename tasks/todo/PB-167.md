# PB-167 — Frontend: page integration — flag-gated nav, pay-to-play flow, scorecard, submit, resume

Wire the game into the app shell the same way Community R&D is wired.
Plan §4.

## Frontend
- `src/frontend/src/GolfGame.tsx` page; third nav pill ("Burn Putt") shown
  only when the `mini_golf` flag is on (solid-pill active state, like the
  other pages); dashboard promo card variant optional.
- Pay flow (house two-step tx pattern): Play button shows fee from
  `get_golf_info()` → `get_golf_deposit_address` → ICP ledger
  `icrc1_transfer(fee + 3×10_000 + 10_000)` → `start_golf_round` → into
  hole 1. Errors surfaced with the standard error panel styling.
- During play: shots accumulate locally as `(hole, angle_mrad, power)`
  exactly as quantized; scorecard between holes; final scorecard →
  `submit_golf_score` → success state links to the leaderboard tab.
- Resume: on mount, `get_my_golf_round()`; an unsubmitted `Paid` round
  rebuilds state by locally replaying its recorded shots (determinism) and
  continues at the next hole; an expired round shows a "round expired"
  notice (fee is not refundable — copy must say so before payment).
- Anonymous users see the course in free-play demo mode (no fee, no
  submission) with a sign-in CTA — progressive disclosure per GOALS.md.

## Acceptance Criteria
- [ ] Flag off ⇒ no nav entry, direct state inaccessible.
- [ ] Full paid round on local: fee leaves wallet, score submits,
      leaderboard row appears.
- [ ] Refresh mid-round resumes correctly at the right hole/stroke count.
- [ ] Fee + non-refundability disclosed in the modal BEFORE transfer.
- [ ] Free-play demo never calls update methods.
