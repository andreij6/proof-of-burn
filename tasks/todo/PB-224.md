# PB-224 — Test infrastructure: oracles, generators, golden-scenario DSL, soak harness

Plan: `plans/poker/09_test_plan.md` (Layer 0). **Build BEFORE PB-202/203 —
the engine is written against these oracles, not the other way around.**

## Scope

- **Reference 7-card evaluator**: enumerate all 21 five-card combos, rank by
  explicit textbook rules; slow, obvious, test-module only.
- **Per-chip pot oracle**: distribute committed chips one at a time to the
  best eligible covering hand — side pots / odd chips / dead money from
  first principles.
- **Legal-action generator** (random walk over `legal_actions`) + hostile
  twin emitting illegal actions; seeded, reproducible.
- **Golden-scenario DSL**: `table().seats(&[…]).button(n).act("p1 raise
  150")….assert_stacks(&[…])` builder so the 20-case corpus (doc 09 Layer 2)
  reads like hand histories.
- **Soak harness**: N seats × preset scripts × M hands × seed list; used at
  10k hands in CI and 1M hands as the pre-M2 gate; prints invariant
  reconciliation + panics summary.
- Mutation checklist documented in the test module header (doc 09) as the
  PB-203 PR review gate.

## Acceptance

- Oracles agree with hand-computed fixtures (a dozen worked examples in
  comments); generator produces only-legal / only-illegal as configured;
  DSL round-trips a documented example; soak harness runs 10k hands under
  CI time budget with a stub engine (replaced by the real one in PB-203).
