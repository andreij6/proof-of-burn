# PB-166 — Course pack v1: 9 original holes, schema, hash pinning

Original level content + the versioning that ties scores to it. Plan §5,
decision #6.

## Deliverables
- JSON schema (documented in `docs/GOLF_PHYSICS.md` or alongside): hole =
  { walls[], sand[], water[], tee, cup, par }, geometry restricted to
  axis-aligned + 45° segments per the physics spec; canonical serialization
  rule (sorted keys, no whitespace) for hashing.
- `src/frontend/src/golf/courses/v1.json`: 9 **original** holes with a
  difficulty ramp — 2 straightforward par-2s, 3 bank-shot par-3s, 2
  sand-heavy par-3s, 1 water-carry par-4, 1 finale par-4 (par total ≈ 27).
  Layouts designed by us; no resemblance to the reference game's holes.
- SHA-256 of the canonical pack = `course_version`; helper script or test
  that recomputes and asserts the pinned hash; the same file is a fixture
  for the Rust validator (PB-169).
- A 3-hole `dev.json` mini-course for fast local verification.

## Acceptance Criteria
- [ ] Every hole completable at par by a scripted shot sequence (each
      hole's par-line shots added as golden-style vectors).
- [ ] Pack hash is stable across machines (canonicalization tested).
- [ ] Geometry validator rejects out-of-spec segments (non-45° diagonals).
- [ ] Admin runbook line: how to pin a new version via
      `admin_set_golf_course` and what it does to leaderboards.
