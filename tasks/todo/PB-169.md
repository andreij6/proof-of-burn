# PB-169 — Anti-cheat Phase 2: Rust replay validator + score-voiding sweep

Close the Phase-1 trust gap: the canister replays submitted shot logs and
voids scores that don't reproduce. Plan §6, decision #4. Must land before
any prize/payout feature is ever attached to the leaderboards.

## Backend
- `golf_physics.rs`: port of the PB-160 spec — identical fixed-point
  arithmetic, sine LUT, constants. `cargo test` runs the SAME
  `golden.json` vectors as vitest (course pack v1 as fixture).
- Course pack embedded (or chunk-uploaded by admin) and hash-checked
  against `golf_course_version` before any validation.
- Sweep task `validate_golf_scores()` on the 300 s timer: pick up to 2
  unvalidated rounds currently in any leaderboard top 10; replay shot log;
  - match ⇒ `validated = true`;
  - mismatch ⇒ status `Voided`, remove from both leaderboards, audit
    `golf_score_voided` (player + round id).
- Instruction-budget note measured and documented (steps/round, cycles).

## Acceptance Criteria
- [ ] Golden vectors green in cargo; CI fails on TS/Rust divergence.
- [ ] PocketIC: a fabricated shot log that doesn't reach the claimed
      strokes gets voided by the sweep and disappears from the board.
- [ ] Honest round submitted via the real client validates clean.
- [ ] Per-sweep validation work bounded (≤ 2 rounds) and measured.
