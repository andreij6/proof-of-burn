# PB-148 — Fix CMC cycle top-up: use legacy `transfer` not `icrc1_transfer`

## Problem

`settle_burn_split` and `cycle_topup_check` send ICP to the CMC via
`icrc1_transfer` (ICRC-1 format). The CMC's `notify_top_up` rejects these with:

```
InvalidTransaction: Notification transaction must be of type Transfer
```

The CMC requires a **legacy** `transfer` call (AccountIdentifier format) so the
resulting block is of type `Transfer`, not `Icrc1Transfer`. The current code
records ICRC-1 blocks, which the CMC does not accept.

Discovered during PB-147 local verification. The PocketIC integration tests pass
because PocketIC's CMC accepts ICRC-1 transfers; the local `icp` CLI CMC does not.

The CMC subaccount was also wrong (always `None`); that was fixed in PB-147 via
`principal_to_subaccount`. This task covers the remaining ledger method mismatch.

## Fix

For transfers destined for the CMC (cycles top-up only), call the ICP ledger's
`transfer` method with an AccountIdentifier destination instead of `icrc1_transfer`.

Affected call sites:
- `settle_burn_split` — backend CMC transfer and frontend CMC transfer
- `finalize_pool_registration` — backend CMC transfer and frontend CMC transfer
- `cycle_topup_check` — treasury → CMC transfer

All other transfers (treasury, user refunds) should remain on `icrc1_transfer`.

- [ ] `cycle_topup_check` successfully tops up backend cycles from treasury on local.
- [ ] All existing unit + PocketIC integration tests continue to pass.
