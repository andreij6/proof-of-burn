# PB-131 — Re-add NNS Governance `get_full_neuron` types + call

The old register/verify flow's NNS types (`Neuron`, `NeuronId`, `Followees`,
`Result_2` wrapper) were removed. Re-add the minimal set needed to call NNS
Governance `get_full_neuron` and read hotkeys / followees / voting power.
Plan §6 (lib.rs), §2 verification.

## Backend
- Re-add candid types for the `get_full_neuron(u64) -> Result` response:
  `NeuronId`, `Followees`, and `Neuron` with at least: `hot_keys: Vec<Principal>`,
  `controller: Option<Principal>`, `followees: Vec<(i32, Followees)>` (topic →
  followee ids), `cached_neuron_stake_e8s: u64`, and the voting-power field.
- Add an async helper `get_full_neuron(neuron_id) -> Result<Neuron, String>` that
  calls NNS Governance (`rrkah-fqaaa-aaaaa-aaaaq-cai`).
- Add small pure helpers used by verification:
  `neuron_has_hotkey(&Neuron, Principal) -> bool` and
  `neuron_follows(&Neuron, leader_id, topic) -> bool`.
- Confirm the Governance topic id for **Governance** (expected `4`) and define a
  named constant `TOPIC_GOVERNANCE`.

## Acceptance Criteria
- [ ] Backend compiles with the re-added types; `cargo build -p backend` clean.
- [ ] `neuron_has_hotkey` and `neuron_follows` have unit tests over mock `Neuron`
      values (present/absent hotkey; following/not-following the leader).
- [ ] `TOPIC_GOVERNANCE` constant documented with the verified topic id.
- [ ] `get_full_neuron` decode shape matches the live NNS candid (verified by a
      decode unit test against a sample response, or noted for integration).
