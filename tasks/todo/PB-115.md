# PB-115 — Vote against `nns_proposal_id`, not the internal proposal key

`process_proposal_cutoff` passes the internal proposals-map key (`pid`) to `cast_nns_vote` as the NNS proposal id. The `Proposal` struct carries a separate `nns_proposal_id: Option<u64>` field precisely because the internal key and the real NNS proposal id are different namespaces.

## Finding F-108
`src/backend/src/lib.rs`:
- `process_proposal_cutoff(pid)` calls `cast_nns_vote(config.primary_neuron_id, pid, vote_choice)`.
- `cast_nns_vote` then sends `RegisterVote { proposal: Some(NnsProposalId { id: proposal_id /* = pid */ }), .. }`.

Today the seeded mock proposals use the same number for both (e.g. `138402`), so it works by coincidence. Once real NNS proposals are ingested ([[PB-031]]) and the internal key diverges from the NNS proposal id, **the neuron will register its vote against the wrong NNS proposal** — or against a non-existent one, which (post-[[PB-110]]) marks the proposal `"failed"` and refunds instead of voting.

## Scope
- In `process_proposal_cutoff`, resolve the NNS proposal id from `proposal.nns_proposal_id` and pass that to `cast_nns_vote`.
- If `nns_proposal_id` is `None`, do **not** call the NNS — treat as a misconfiguration: skip the vote, leave funds refundable, and log/audit it. Never fall back to the internal key.
- Audit the rest of the codebase for the same internal-key-vs-nns-id confusion (e.g. settlement, vote records, frontend `getProposalTitle` lookups by id).

## Acceptance criteria
- A proposal whose `nns_proposal_id` differs from its internal key casts the NNS vote against `nns_proposal_id`.
- A proposal with `nns_proposal_id == None` does not call `manage_neuron` and its commitments are refunded, not burned.
- Covered by an integration test with divergent ids (extends [[PB-112]]).

## Notes / pitfalls
- Keep `VoteRecord.proposal_id` consistent with whatever the UI uses to look up titles — decide whether records are keyed by internal id or NNS id and apply it uniformly.
- This is latent today (ids coincide in seed data) but becomes a real mis-vote the moment live NNS proposals are wired in.
