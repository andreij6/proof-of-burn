# PB-163 — Backend: weekly + monthly leaderboards, queries, pruning

Best round per player per period. Plan §1 (GOLF_BEST), decision #7.

## Backend
- Period math (pure fns + unit tests): `week_id = epoch_days / 7`
  (document the Thursday-00:00-UTC boundary), `month_id = year*12 + month0`
  via civil-date conversion from ns timestamp. No floats, no time crates —
  hand-rolled civil-from-days (documented algorithm).
- `GOLF_BEST` stable map at MemoryId 21, key
  `LeaderKey { kind: u8, period_id: u32, player }`, value
  `BestScore { total_strokes, submitted_at, round_id, course_version }`.
- On `submit_golf_score`: upsert weekly + monthly rows iff strictly better
  (fewer strokes; tie keeps the earlier submission).
- `get_golf_leaderboard(kind, period_id: opt u32) -> Vec<LeaderboardRow>`:
  rows of the requested (default: current) period sorted by strokes then
  submitted_at, truncated to 100; plus the caller's own row + rank appended
  when outside the top 100.
- `get_golf_info()` query: flag, fee, course version/holes/par, TTL,
  current week_id + month_id, period reset timestamps.
- Sweep prune: drop `GOLF_BEST` rows with period older than 12 months.

## Acceptance Criteria
- [ ] Period-id unit tests pin known dates (incl. month/year boundaries and
      a week boundary at Thursday 00:00 UTC).
- [ ] Worse/equal later score does NOT displace an existing best (tested).
- [ ] Leaderboard sorted, capped at 100, caller's rank correct at 1, 100,
      and 101+ (tested).
- [ ] Prune removes only rows older than 12 months (tested).
