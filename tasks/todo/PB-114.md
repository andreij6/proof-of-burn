# PB-114 — Frontend component / integration tests

[[PB-093]] added Vitest with **pure-logic tests only** (`utils.test.ts`). `@testing-library/react` is installed but no component renders are tested, despite the UI now carrying real money-moving flows and conditional gating.

## Scope
Component/integration tests (jsdom + Testing Library) with a mocked backend actor:

- **Tier gating:** Tier 0–3 render the correct sections and lock states; gated content is not interactable.
- **Three-section partitioning:** a proposal moves Open → Committed → History based on the user's commitment status and proposal state; oversubscribed bar renders `>100%` label.
- **Stance-first commit flow:** ADOPT/REJECT opens the modal with stance preset; amount validation (min 1 ICP, stake cap, wallet balance) shows inline errors; Confirm disabled until valid.
- **TransferError handling:** a mocked `icrc1_transfer` returning each `Err` variant renders the human-readable message (no "Do not know how to serialize a BigInt" regression).
- **Success copy:** post-commit message emphasises permanent burn (no "keeps the app running").
- **Mainnet vs local:** simulator/faucet sidebar hidden when host is non-local.

## Acceptance criteria
- `npm test` runs component tests green alongside the existing util tests.
- Each of the brief's key interactions has a loading / success / error assertion.
- Gating is asserted to be backed by the actor result, not just hidden in the DOM.

## Notes / pitfalls
- Mock `@icp-sdk/auth` and the generated actor; don't hit a live replica in unit tests.
- Keep the BigInt-serialization regression test permanently.
