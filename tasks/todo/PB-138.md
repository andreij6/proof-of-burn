# PB-138 — Pool revenue share: `distribute_pool_rewards` (treasury-funded)

Pay the 25% pool share once per proposal, out of the treasury — **without
touching the per-commitment settlement path**. Plan §4 (review issue #2 fix).

## Backend
- `settle_burn_split` and `process_proposal_cutoff` remain **unchanged**
  (settlement stays 50% treasury / 25% backend / 25% frontend, 3 transfers).
- Add `pool_distributed: bool` to `Proposal` (`#[serde(default)]`).
- `distribute_pool_rewards(proposal_id)`:
  1. If `pool_distributed` → return (idempotent).
  2. Set `pool_distributed = true` **first**, then transfer (bias against
     double-pay; a mid-trap leaves payouts owed → admin recourse via audit log).
  3. `pool_share = total_burned_e8s / 4` (25%).
  4. Collect **Active** pool neurons, sort by VP desc, take top 25, dedup.
  5. Empty set → no transfer (treasury keeps the full 50%). Otherwise transfer
     `pool_share / n` (minus 0.0001 fee) from the **treasury subaccount** to each
     neuron's `registered_by` default ICRC account. Audit-log each payout.
- Hook `distribute_pool_rewards` to run after a proposal is fully settled (end of
  settlement or via the existing sweep timer).

## Acceptance Criteria
- [ ] Effective split with a non-empty pool is 25/25/25/25; with an empty pool it
      stays 50/25/25 (no pool transfer).
- [ ] Pool payouts come from the **treasury subaccount**, not per-commit escrow;
      `required_deposit` / commit reserve are unchanged.
- [ ] `pool_distributed` prevents a second payout for the same proposal
      (idempotent) — integration test calls it twice.
- [ ] Top-25 cap enforced; with > 25 Active neurons only the highest-VP 25 are
      paid, split equally.
- [ ] Unit test for the share math (25% of total, equal split, remainder/fee
      handling); integration test for an end-to-end settle + distribute.
