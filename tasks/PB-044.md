# PB-044 — Commitment cap enforcement (≤ neuron holdings)

A user cannot commit more than they hold across their neuron(s) for a single vote.

## Scope
- Resolve the user's neuron holdings (reuse the neuron read from [[PB-022]]).
- Reject commits where `amount_e8s + existing_commit > holdings_e8s`.
- Surface `holdings_e8s` to the SPA for inline cap display.

## Acceptance criteria
- Over-cap commit is rejected with a clear error; at/under-cap succeeds.
- SPA shows available holdings as commitment context (Tier 2).

## Notes / pitfalls
- Holdings can change between check and commit — re-validate inside the guarded commit path (TOCTOU).
