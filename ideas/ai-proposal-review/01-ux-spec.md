# AI Proposal Review — UX Spec

Companion to [README](README.md). Frontend lives in `App.tsx` (proposal cards +
modals) with shared primitives from `ui.tsx`.

## 1. The "AI Review" button

- Added to each proposal card's action row (Open / Committed / Past), next to the
  existing **Share** button (`App.tsx` ~2864 / ~3027).
- **Enabled** when signed in **and the user holds any supported token with a
  balance ≥ the fee** (D2): check `holdings` (ICP) plus `tokenBalances.{ckbtc,
  cketh,ckusdc,ckusdt}` against the per-token quoted fee. Otherwise **disabled**
  with a tooltip:
  - not signed in → "Sign in to use AI Review"
  - signed in, no payable balance → "Add ICP or a ck-token to use AI Review"
- Icon: `bulb` or `spark` (both in `iconPaths`). Label: **"AI Review"**.
- **No "View AI Review"** state — reviews aren't stored (D5); every click is a
  fresh paid review.

## 2. The confirm dialog (clone of the Explorer listing modal)

Reuses `MODAL_OVERLAY` / `MODAL_CARD` and the token-picker + live-quote pattern
from `Explorer.tsx`'s submit-listing modal.

```
┌─ AI Review · Proposal #12345 ───────────────┐
│  Get an independent AI read on this proposal │
│  — is it good or bad for the IC, and why.    │
│                                              │
│  Pay with:  [ICP] ckBTC ckETH ckUSDC ckUSDT  │
│  Fee:  0.0531 ICP  = $0.25   (locked 15 min) │
│  Your balance: 1.20 ICP                      │
│                                              │
│  ⓘ AI opinion, not financial advice. One     │
│    node relays the request (non-replicated). │
│                                              │
│            [ Cancel ]  [ Pay & review ]      │
└──────────────────────────────────────────────┘
```

- **Quote**: `get_ai_review_quote(token)` → reuses `explorer_usd_rate_e8s` +
  `explorer_quote_amount` with `AI_REVIEW_FEE_USD_E8S` (Q3). Price locked 15 min
  (same `ExplorerQuote` TTL).
- **Deposit + pay**: identical 2-step to `submit_dapp` — transfer the quoted
  amount into the per-caller AI escrow subaccount, then call `request_ai_review`.
- **Treasury-gate awareness**: because failure refunds are treasury-fronted, if
  `globalStats.treasury_can_front_fees` is false the dialog shows "AI Review is
  paused — treasury can't cover fees" and disables Pay (consistent with the
  commit/unstake gating already shipped).

## 3. The in-flight + result states

A stepper while the outcall runs (input disabled):
`Charging fee…` → `Asking Gemini…` → `Reading the linked PR…` (if any) → `Done.`

**Result card** (structured, from Gemini `responseSchema`):

```
┌─ AI Review · Proposal #12345 ───────────────┐
│  ●  VERDICT: NEGATIVE for the IC            │  ← green/red/amber chip
│                                              │
│  Why:                                        │
│   • <rationale bullet 1>                      │
│   • <rationale bullet 2>                      │
│   • <rationale bullet 3>                      │
│                                              │
│  IC impact: <one-paragraph synthesis>        │
│  Sources: PR #4821 (dfinity/ic)  ↗           │  ← if URL-context used
│                                              │
│  ⓘ Generated by Gemini · AI opinion, not     │
│    financial advice · reviewed 2026-06-19    │
│                                              │
│        [ Share on X ]      [ Close ]         │
└──────────────────────────────────────────────┘
```

- **Verdict** chip tones: `ok` (positive), `danger` (negative), `gold`/`pending`
  (mixed/neutral) — reuse the design-system chip tones.
- **Sources** line only if the GitHub URL-context fetch contributed (Gemini
  returns `url_context_metadata`).

## 4. Share on X

Reuse `shareProposalOnX`'s pattern (`twitter.com/intent/tweet`). **The tweet body
is the AI-produced `tweet_text`** (D5) — Gemini returns a ready, ≤~270-char,
verdict-leading rendering, so the client doesn't compose it. The client appends:
- `url` = the proposal deep-link (`nnsProposalLink(p)`), and
- ensures the **"AI opinion, not advice"** framing is present (D6) — either Gemini
  includes a short tag, or the client appends one within the char budget.

(No stored-review permalink — D5 stores nothing; the text lives only in the tweet
and the open app session.)

## 5. Empty / error states

- **Outcall failure** (non-200, timeout, unparseable): result card shows
  "Couldn't complete the review — your fee was refunded." Fee auto-refunded
  (Part D of backend spec). No partial charge.
- **No GitHub link in proposal**: skip the URL-context step silently; review runs
  on title+summary only; "Sources" line omitted.
- **Rate / abuse guard**: a per-caller cooldown + a global daily cap (backend);
  the button shows "Try again in N min" when the cooldown is active.

## 6. Local-dev toggles

Per the project's dev-controls pattern (`usePageDevControls`): a
`dev_mock_ai_review(proposal_id, verdict)` that stores a canned review without an
outcall or fee, so all result states (positive/negative/mixed/error) can be
previewed offline.
