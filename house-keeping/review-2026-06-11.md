# Review 2026-06-11 — questionable / deferred items

A 7-angle review (3 correctness, 3 cleanup, 1 architecture) ran over the
June 10–11 feature batch (Dapp Explorer, Arcade/Mini Golf, Co-Founders,
Twitter share + hash routing, ckUSDC/ckUSDT, Caldera rename). **All clear
bugs were fixed in the same pass** (see the commit referencing this file).
The items below are real but either need a design decision, carry upgrade
risk disproportionate to their current impact, or are pure refactors. None
blocks the mainnet deploy: every money-moving path they touch is either
fixed, feature-flagged dark, or unaffected.

## Architecture / refactors (do as one consolidation pass)

1. **Token registry.** Adding a token currently touches ~12 backend sites
   (ExplorerToken enum, index/decimals/xrc-symbol/default-rate/ledger/fee
   match fns, the `[(u64,u64); 5]` rate-cache array — NOT compiler-checked
   against the enum size, a stale array panics at runtime — ExplorerInfo's
   per-token field pairs, admin_set_explorer_ledger, Config) plus 4 frontend
   copies of the same label/decimals/fee/ledger table (Explorer TOKEN_BASE,
   Arcade PAY_TOKENS, App getWalletTokenMeta, IdeaBoard tokenMeta).
   Consolidate into one registry per layer. Consider folding ExplorerToken
   into IdeaToken (additive candid change) so `admin_set_token_ledger` and
   `admin_set_explorer_ledger` collapse into one endpoint — today an
   operator must remember which endpoint wires which token.

2. **Quote-lock unification.** EXPLORER_QUOTES and ARCADE_QUOTES are
   near-identical stores with copy-pasted quote endpoints (the arcade one
   repurposes `days: 1` to mean "one $1 unit"). One store keyed by
   (purpose, principal) + a shared `lock_quote` helper.

3. **Escrow helper.** The deposit-subaccount → balance-check → transfer
   flow exists 5+ times with per-copy drift (one unchecked add was found
   and fixed this pass). Shared `derive_domain_subaccount(tag, user, salt)`
   (6 copies of the sha256 ritual today) + `collect_escrow(...)`.

4. **Small dedups.** `require_feature(flag)` for the 6 identical flag
   guards; `log_event` for the 6 inlined AuditLogEntry blocks (they already
   disagree on what `proposal_id` holds: 0 / strokes / settlement month);
   frontend MODAL_OVERLAY/MODAL_CARD/LABEL_STYLE (5 copies) and the
   Prev/Next pager (4 copies) → ui.tsx; `shadeHex` (Arcade) ≡ `shade`
   (MiniGolf) → arcade/engine.ts.

## Scalability (fine at current sizes; fix before real adoption)

5. **arcade_access vote scans.** Now short-circuited for stakers (fixed),
   but for non-stakers it still scans all LOSSLESS_VOTES + COMMITMENTS per
   call, and both grow forever. Right fix: a `LAST_PARTICIPATION:
   StableBTreeMap<Principal, u64>` updated at vote/commit time → O(log n).

6. **get_cofounder_info** sums every member's claimable per query (cap
   10k). Maintain a running `unclaimed_total_e8s` counter in CoFounderState
   updated at allocation/claim/expiry. Deferred: touches the settlement
   state machine, low value at current member counts.

7. **submit_arcade_score rank scan** iterates all games' scores. The key
   sorts (game, player), so a prefix range scan bounds it to one game.

## Product / design decisions needed

8. **ArcadeInfo dead fields & palette source of truth.** has_stake,
   voted_recently, customize_fee_usd_e8s, hair/skin/outfit_options are not
   read by the UI; the editor uses the local palette arrays. If someone
   adds a palette color in engine.ts without bumping CHARACTER_*_OPTIONS,
   users can pay the deposit and then get INVALID_CHARACTER_OPTION. Either
   make the UI consume the backend counts or drop the fields.

9. **Settled-proposal share links degrade silently.** Cards in the
   committed tab now carry the anchor id (fixed), but a cold-load of a
   share link for a proposal that's no longer in the default Active tab
   lands on the voting page without switching tabs/scrolling. Decide: tab
   auto-switch, a proposal-detail view, or accept the degradation.

10. **dev_set_cofounder_preset fabricates live money state** (claimable
    shares with an empty pool, mock neuron id) — local-only and labeled,
    but Claim fails with CLAIM_TRANSFER_FAILED inside presets and the next
    sweep "settles" fiction, which can burn a debugging session. Either
    seed the local ledger subaccounts to match or quarantine presets from
    the sweep.

11. **Mini-golf state double-booking.** phase/holeIdx/perHole live in both
    React state and the GameRef, synced by hand. Make the ref the single
    owner; mirror display values only. (Works today; refactor with care.)

12. **Hash routing is three coordinating effects.** Fixed the concrete
    bugs (hashchange proposal links, auth-resolution bounces), but the
    single-source-of-truth shape (derive page+proposal from the hash in one
    subscription; nav writes only location.hash) would remove the class.

## Intentional behavior changes (documented, not bugs)

- `coi_entered` localStorage gate removed 2026-06-11 at owner request:
  signed-out visitors at the root ALWAYS see the landing page now (the old
  behavior skipped it for returning visitors). Signed-in visitors bounce to
  the app once auth resolves.
- Leaderboard fairness across admin course edits (scores don't tag a course
  version) — flagged 2026-06-11 when the editor shipped; owner has not
  requested versioning yet.
